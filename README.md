# 贝蒂电竞俱乐部内部管理系统

第一版本地试用系统，供管理员和客服维护客户、会员、陪玩、报价、订单与派单。系统记录外部到账、退款和陪玩应得，不执行真实资金交易。

正式环境使用独立空库和随机账号密码，不创建演示资料；部署目录、服务、备份和证书配置见 [deploy/README.md](deploy/README.md)。本页下方的体验账号仅用于本地演示，不适用于正式网站。

## 本地使用

需要 Node.js 24 或更新版本。首次安装和启动：

```sh
npm ci
npm run build
npm start
```

浏览器访问 http://127.0.0.1:4318 。macOS 也可双击项目内的 `启动贝蒂工作台.command`，此方式在后台运行，启动后可以关闭终端；双击 `停止贝蒂工作台.command` 停止服务。手动执行 `npm start` 时，按 Control+C 停止。

首次启动创建以下本地测试账号及标注为演示的虚构资料：

| 角色 | 账号 | 初始密码 |
| --- | --- | --- |
| root 管理员 | admin | Batty2026! |
| 客服 | kefu | Staff2026! |

登录页点击测试账号即可填入。管理员可以在账号与审计页面创建工作人员、调整授权、停用账号、重置密码；个人密码在右上角菜单修改。

## 账号身份

系统预置唯一的 root 管理员，登录名仍可使用 `admin`。普通管理员默认拥有日常业务、规则设置、报表、审计及备份能力；人员删除、已结算金额更正和管理其他管理员账号属于可单独授予的高级权限。root 主要负责这些高级授权和特殊兜底。root 账号不能通过账号管理接口修改、停用、降级或删除；本人可通过右上角菜单修改密码。

普通管理员默认可管理客服和股东账号。root 可在管理员表单分别勾选“人员删除”“已结算金额更正”和“允许管理其他管理员账号”；高级授权只能由 root 授予或收回，获授权的管理员不能给自己或其他管理员继续转授，也不能借改角色隐式收回。重置其他管理员密码时，不能接管持有自身未获高级权限的账号。管理员可以给客服勾选普通业务直办权，客服不能获得管理员高级权或审核别人的申请。账号停用或授权变化会使目标账号原有登录失效，历史业务记录保留。

客服原有充值、结清、档案维护、导出等基础权限继续分别控制；这些基础项目未授权时不能办理。订单取消、未消费退款、已消费售后退款、服务提前终止、资料删除与归档、充值更正及本金退款可以分别勾选直接办理权；未获得直办权时可提交申请。客服的客户与订单处理范围为当前本人负责的数据，读取他人业务不代表可以变更。旧账号已有的普通退款授权继续覆盖未消费部分，新增加的直办权限默认关闭。

股东登录后仅显示数据报表，可筛选和刷新经营数据、查看派单应得与结算记录，不提供业务处理、审批、通用导出或整库备份入口。股东报表使用独立字段投影，不下发客户与陪玩的联系方式、内部备注、账号清单、审计和实际后台配置。

旧版本数据库首次启动时，将内置固定编号 `admin` 的启用管理员升级为 root，保留原登录名、密码、业务关联及数据，并使该账号旧登录失效；重复启动不会重置账号。若原始管理员已停用、降级或缺失且库中没有 root，启动会拒绝自动指定，请先核对数据库并备份。新旧库均通过数据库唯一约束和保护触发器限制 root 身份。

## 已实现的工作流程

1. 客户建档：称呼、号码类型与号码，支持标签、跟进人、历史订单和流水；余额从流水产生。
2. 充值与会员：首充、续充、升级、期初余额分别登记，外部到账需要参考号。升级只看本次套餐充值；会员无自动到期。白银、黄金的权益选定后锁定；升级沿原权益路线，已用微信名额计入升级后总名额。
3. 报价：单陪、双陪、混档与新客体验组合；每条报价各选一种比例折扣，默认已登记的会员折扣，更优惠选项只提示。
4. 客户确认：保存订单和报价版本，复制对客确认单；客服记录客户确认后才可结清。
5. 结清：单一主客户的钱包、外部转账或两者组合；同一到账凭证不能重复入账，余额不能透支，重复确认不会重复扣款。
6. 派单与服务：按服务明细关联匹配成员，支持部分派单、预约冲突提示、开始结束、换人、赠时和补打记录。
7. 退款与更正：人工核实退款金额，按原付款来源分别记录；余额退款返还钱包，外部退款在实际退回后登记凭证。未消费退款和已消费售后退款分别授权，无直办权时进入单级审批。
8. 数据与审计：客户、订单、流水、派单及审计 Excel/CSV 导出；每个关键操作记录操作者、时间及变更前后值。陪玩应得金额由管理员人工录入汇总。

## 单级审批与处理待办

审批与待办只包含订单处理、资料处理、资金更正三类申请。权限内直接办理并留痕，超出权限时提交给具备对应能力的管理员；高级事项可以由已获授权的其他管理员处理，无人具备权限时由 root 兜底。申请人不能审核自己的申请，客服获得直办权也不能审核他人。普通申请不需要先经管理员、再经 root 两轮批准。

申请状态为待审核、处理中、已完成、已驳回、已撤回和已失效。待审核可以撤回，驳回必须说明原因；申请本身不停止服务、不改余额。批准时重新核验金额、付款来源、服务和结算进度，关键业务变化后不能按旧方案执行。普通备注和确认图复制不应改变审批实质。重复提交和多人同时操作只允许一份有效结果；已有申请可以在业务详情或统一待办继续处理。

订单取消按历史阶段判断：本人负责且从未确认、未付款、未服务的订单可由客服填写原因取消；曾经确认过、零元结清或曾开始服务的订单不能因改单、换人或退款归零降回低阶段权限。未开服默认全退，开服后的消费、退款和陪玩应得由有权限的处理人分别核定。已完成订单保留履约历史，通过售后退款处理。取消整单或终止指定服务项均需保留已完成、已换人和已产生应得记录，关联续单、补款单逐笔核对，不自动联动。

### 批准退款不等于钱已退回

- 钱包退款在批准或直办时与余额流水、服务变更、操作记录一起保存，退回原主客户的钱包。
- 外部退款仍需工作人员在线下实际操作。批准后显示处理中，登记真实退款凭证后才增加实际已退款金额；混合退款可以出现钱包已退、外部待退。
- 已批准尚未执行的退款占用对应来源的可退额度，其他直接退款或审批不能重复占用；原钱包和外部付款来源分别限制上限，不能互换或超退。
- 外部凭证共用查重；记账失败使用同一申请和凭证重试，不应再次线下转账。退款计划改变时重新核定，技术重试无需重新申请。
- 客户退款不自动清零陪玩应得；已结算金额更正要有高级授权，追加差额记录并保留原应得及原结算。
- 充值本金退款须核定会员资格和剩余权益，可以确认维持当前权益；系统不自动降级或追回已使用权益，历史订单不重算。

### 停用、归档和回收站

误建且无业务关联的客户、陪玩资料可以软删除；有交易历史的客户走停用归档，余额和负债继续保留。陪玩停用立即阻止新派单，有预约或服务中安排时须先处理这些安排；未结算应得继续显示在财务记录中。

客服账号可以先停用使登录立即失效，再将客户、未完订单及草稿交接给指定工作人员后删除。人员删除保留稳定编号、历史操作者、订单和账务，在回收站恢复后仍需按规则启用账号，不恢复旧会话。第一期不提供物理清除交易和审计历史的入口。

## 开单暂存与恢复

开单页支持“暂存草稿”，未选客户、未填完整的服务也能保存。暂存后可从侧栏“开单草稿”继续；草稿按当前客服账号隔离，不扣余额、不计入正式订单统计。修改时切换页面或退出登录，会提示“暂存并离开 / 继续填写 / 放弃本次修改”；已暂存的内容不会因放弃后续修改而删除。

填写中的改动同时保存在当前浏览器的本机恢复备份中，刷新或关闭前会触发浏览器离开提醒。重新打开时可恢复；选择稍后处理的备份仍可在草稿箱找到。本机备份不等于已暂存到账户，换电脑前应点击暂存。生成正式确认单时，草稿与订单在同一事务内关联并移出草稿箱，避免重复开单；多窗口修改同一草稿有版本冲突保护。

## 费用核对与特殊情况增减款

开单页和订单详情展示服务单价、时长、附加费、双陪减免分摊、折扣及结果计算式。旧订单使用已保存的报价金额解释，不随现价目表重算；整单汇总使用各项折后金额，避免重复扣优惠。客户列表及搜索选项使用不同颜色、图标和文字区分会员卡；陪玩列表、报价指定与派单候选均显示已登记的性别。

订单页的“复制客户确认图”将服务内容、各项报价和价格汇总生成固定宽度 2200 像素的横向卡片 PNG，按服务项和文字长度向下延伸。图片不展示详细计算步骤、公式或分摊过程；后台费用计算明细仍可展开查看。预览使用同一张实际输出图片，可复制图片或下载 PNG；浏览器不支持图片剪贴板或拒绝复制时会显示预览并提示下载，不会改为复制文字。超长图片分带渲染后合成一张 PNG，避免单个画布的高度限制；异常大量文本超过安全总尺寸时明确提示，不会截断内容。

确认图仅包含对客安排、保存的报价版本、各项价格、汇总金额和服务约定，不包含内部备注、客户联系方式或成员应得。预览读取最新订单，复制或下载前同时校验订单版本与报价版本。生成图片的请求会保留版本审计，不等于图片已发送、客户已确认或订单已收款。

管理员可在订单“更多操作 → 特殊情况增减款”中填写本次金额及原因。未结清订单累加费用调整，生成新版报价并清除旧客户确认；不修改原服务单价，不自动扣余额。已结清订单减款进入原付款来源的退款核实表单，增款生成关联补款单；原收款记录保留。补款说明显示在客户确认单中，需独立确认、结清，计入账目但不产生陪玩派单。所有增减款保留操作者、原因、时间、前后金额和版本，重复提交同一请求不重复记账。

## 计价口径

- 统一使用“娱乐陪”，与原资料的轻松陪是同一档。
- 金额计算单位为分，展示为人民币元；先计算基础价和附加项，再减整组双陪优惠，最后应用该条选中的折扣。
- 同档双陪按价目表整组每小时减免一次；混档双陪由客服填写整组每小时减免，按基础金额比例分摊到两条报价，尾差保留在最后一条。
- 双陪两条3小时服务不合并认定6小时包时。时长不同或预约错开时，整组减免仅适用于共同服务的时段。
- 指定女陪按对应服务人员加价；一陪二按该项服务加价，娱乐陪免加价。
- 99元体验单是独立报价，客服明确本次模式、人数、时长和保障内容，新客暂由客服认定。
- 收费时间与赠时、补打分开登记；续单生成关联的新订单，不事后自动补扣。
- 免费补时与补打在原派单中记录；已完成订单添加补打记录不会自动重新派单，由客服协调并记录。正式服务宜在约定保障履行完毕后登记完成。

## 数据保存与备份

正式业务数据位于 `data/batty.sqlite`，重启服务会保留数据。首次启动后不会反复覆盖演示或试用资料。后台“规则与设置”可下载一致性 SQLite 备份。

恢复备份时，先停止服务，保留当前 `data` 文件夹副本，再将备份替换为 `data/batty.sqlite`，清理对应旧的 `-wal`、`-shm` 临时文件后重启。不要在服务运行时直接替换数据库。

本地数据库和依赖文件不纳入版本控制。以后部署服务器时使用独立配置、迁移或保留试用数据，再配置正式域名、HTTPS与备份计划。

## 开发和验证

```sh
npm run dev    # 前端5173，后端4318
npm run check  # 前后端类型检查
npm test       # 真实接口事务、权限及计价测试
npm run build
```

测试使用独立临时数据库，不修改本地试用数据。环境变量 `HOST`、`PORT`、`DB_PATH` 可通过复制 `.env.example` 为 `.env` 配置。页面与接口采用同源会话，操作者由服务端登录状态确定；业务日志在应用内只追加。

跨流程回归覆盖零元结清后的派单与取消、整单减免后的客服退款上限、赠时重试防重复、主客户余额隔离，以及首次草稿暂存响应丢失后的重试。恢复草稿会保留原版本基准；冲突不会因再次备份而消失。订单操作保存中禁止切页、退出或关闭表单；服务端已保存但列表刷新失败时，会明确提示保存成功并保留返回记录。退出或换号后会丢弃旧请求的刷新结果与失效通知。
