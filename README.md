# 贝蒂电竞俱乐部内部管理系统

第一版本地试用系统，供管理员和客服维护客户、会员、陪玩、报价、订单与派单。系统记录外部到账、退款和陪玩应得，不执行真实资金交易。

正式环境使用独立空库和随机账号密码，不创建演示资料；部署目录、服务、备份和证书配置见 [deploy/README.md](deploy/README.md)。本页下方的体验账号仅用于本地演示，不适用于正式网站。

## 本地使用

需要 Node.js 24 或更新版本。首次安装和启动：

```sh
npm ci
npm run build
npm start
```

浏览器访问 http://127.0.0.1:4318 。macOS 也可双击项目内的 `启动贝蒂工作台.command`，此方式在后台运行，启动后可以关闭终端；双击 `停止贝蒂工作台.command` 停止服务。手动执行 `npm start` 时，按 Control+C 停止。

首次启动创建以下本地测试账号及标注为演示的虚构资料：

| 角色 | 账号 | 初始密码 |
| --- | --- | --- |
| 管理员 | admin | Batty2026! |
| 客服 | kefu | Staff2026! |

登录页点击测试账号即可填入。管理员可以在账号与审计页面创建工作人员、调整授权、停用账号、重置密码；个人密码在右上角菜单修改。

## 已实现的工作流程

1. 客户建档：称呼、号码类型与号码，支持标签、跟进人、历史订单和流水；余额从流水产生。
2. 充值与会员：首充、续充、升级、期初余额分别登记，外部到账需要参考号。升级只看本次套餐充值；会员无自动到期。白银、黄金的权益选定后锁定；升级沿原权益路线，已用微信名额计入升级后总名额。
3. 报价：单陪、双陪、混档与新客体验组合；每条报价各选一种比例折扣，默认已登记的会员折扣，更优惠选项只提示。
4. 客户确认：保存订单和报价版本，复制对客确认单；客服记录客户确认后才可结清。
5. 结清：单一主客户的钱包、外部转账或两者组合；同一到账凭证不能重复入账，余额不能透支，重复确认不会重复扣款。
6. 派单与服务：按服务明细关联匹配成员，支持部分派单、预约冲突提示、开始结束、换人、赠时和补打记录。
7. 退款与更正：人工核实退款金额，按原付款来源分别记录；余额退款返还钱包，外部退款仅在客服已操作后登记。已开始服务的退款交管理员处理。
8. 数据与审计：客户、订单、流水、派单及审计 Excel/CSV 导出；每个关键操作记录操作者、时间及变更前后值。陪玩应得金额由管理员人工录入汇总。

## 开单暂存与恢复

开单页支持“暂存草稿”，未选客户、未填完整的服务也能保存。暂存后可从侧栏“开单草稿”继续；草稿按当前客服账号隔离，不扣余额、不计入正式订单统计。修改时切换页面或退出登录，会提示“暂存并离开 / 继续填写 / 放弃本次修改”；已暂存的内容不会因放弃后续修改而删除。

填写中的改动同时保存在当前浏览器的本机恢复备份中，刷新或关闭前会触发浏览器离开提醒。重新打开时可恢复；选择稍后处理的备份仍可在草稿箱找到。本机备份不等于已暂存到账户，换电脑前应点击暂存。生成正式确认单时，草稿与订单在同一事务内关联并移出草稿箱，避免重复开单；多窗口修改同一草稿有版本冲突保护。

## 费用核对与特殊情况增减款

开单页、订单详情和客户确认单展示服务单价、时长、附加费、双陪减免分摊、折扣及结果计算式。旧订单使用已保存的报价金额解释，不随现价目表重算；整单汇总使用各项折后金额，避免重复扣优惠。客户列表及搜索选项使用不同颜色、图标和文字区分会员卡；陪玩列表、报价指定与派单候选均显示已登记的性别。

管理员可在订单“更多操作 → 特殊情况增减款”中填写本次金额及原因。未结清订单累加费用调整，生成新版报价并清除旧客户确认；不修改原服务单价，不自动扣余额。已结清订单减款进入原付款来源的退款核实表单，增款生成关联补款单；原收款记录保留。补款说明显示在客户确认单中，需独立确认、结清，计入账目但不产生陪玩派单。所有增减款保留操作者、原因、时间、前后金额和版本，重复提交同一请求不重复记账。

## 计价口径

- 统一使用“娱乐陪”，与原资料的轻松陪是同一档。
- 金额计算单位为分，展示为人民币元；先计算基础价和附加项，再减整组双陪优惠，最后应用该条选中的折扣。
- 同档双陪按价目表整组每小时减免一次；混档双陪由客服填写整组每小时减免，按基础金额比例分摊到两条报价，尾差保留在最后一条。
- 双陪两条3小时服务不合并认定6小时包时。时长不同或预约错开时，整组减免仅适用于共同服务的时段。
- 指定女陪按对应服务人员加价；一陪二按该项服务加价，娱乐陪免加价。
- 99元体验单是独立报价，客服明确本次模式、人数、时长和保障内容，新客暂由客服认定。
- 收费时间与赠时、补打分开登记；续单生成关联的新订单，不事后自动补扣。
- 免费补时与补打在原派单中记录；已完成订单添加补打记录不会自动重新派单，由客服协调并记录。正式服务宜在约定保障履行完毕后登记完成。

## 数据保存与备份

正式业务数据位于 `data/batty.sqlite`，重启服务会保留数据。首次启动后不会反复覆盖演示或试用资料。后台“规则与设置”可下载一致性 SQLite 备份。

恢复备份时，先停止服务，保留当前 `data` 文件夹副本，再将备份替换为 `data/batty.sqlite`，清理对应旧的 `-wal`、`-shm` 临时文件后重启。不要在服务运行时直接替换数据库。

本地数据库和依赖文件不纳入版本控制。以后部署服务器时使用独立配置、迁移或保留试用数据，再配置正式域名、HTTPS与备份计划。

## 开发和验证

```sh
npm run dev    # 前端5173，后端4318
npm run check  # 前后端类型检查
npm test       # 真实接口事务、权限及计价测试
npm run build
```

测试使用独立临时数据库，不修改本地试用数据。环境变量 `HOST`、`PORT`、`DB_PATH` 可通过复制 `.env.example` 为 `.env` 配置。页面与接口采用同源会话，操作者由服务端登录状态确定；业务日志在应用内只追加。

跨流程回归覆盖零元结清后的派单与取消、整单减免后的客服退款上限、赠时重试防重复、主客户余额隔离，以及首次草稿暂存响应丢失后的重试。恢复草稿会保留原版本基准；冲突不会因再次备份而消失。订单操作保存中禁止切页、退出或关闭表单；服务端已保存但列表刷新失败时，会明确提示保存成功并保留返回记录。退出或换号后会丢弃旧请求的刷新结果与失效通知。
